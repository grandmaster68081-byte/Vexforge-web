For Vexforge, work one bounded milestone at a time on `main`. Before each milestone, fetch from `origin` and confirm a clean worktree and `HEAD == origin/main`. Commit and push each completed milestone before beginning another. Never reset, rebase, merge, cherry-pick, or force-push.

Supabase remains authoritative. Do not change live schema, RPCs, RLS, authentication, data, economy, combat settlement, or rewards. Keep the official web portal and `unity/` source intact during bootstrap work. The experimental `unity-bootstrap/` project is the cumulative destination for gradually copying the complete official game; each APK contains all slices completed so far. The user authorizes sequential continuation without per-build prompts after the baseline succeeds. A stage passes when its GitHub Actions run concludes successfully and the cumulative APK/artifact is present, intact, and its downloaded APK hash matches the report. Record BuildReport warning/error counts honestly; per the user's 2026-10-10 direction, those counts alone are non-blocking when the workflow and APK validations pass, and can be collected for review at the end. Stop on an actual failed workflow, missing/invalid APK or artifact, hash mismatch, or unresolved dependency/source issue. This does not authorize the official game workflow or Supabase changes. Follow `docs/vexforge-canonical/UNITY_BOOTSTRAP_WORKFLOW.md`.

The successful historical Bootstrap APK #2 was only a build-pipeline smoke test: the builder generated Unity's default empty scene because no official scene or game content had been migrated. Do not treat that APK as a content milestone. The next migration APK must contain a real official Vexforge scene and a small, dependency-complete slice of official code/assets; never add placeholder or invented game content. The APK SHA-256 was independently matched to its build report. That run saved the first successful `unity-bootstrap/Library` cache; no later build has yet proven cache restoration, so verify and report the next run's actual cache-hit result.

For the active Bootstrap migration, each full APK build adds only 5–7% of the pinned canonical Unity C# line inventory. Measure and record each added source slice in `unity-bootstrap/MIGRATION_MANIFEST.json`; retain all previous slices and compile a complete APK from their accumulated state. Intermediate runtime behavior/scenes may be incomplete, but each Unity C# compile and APK build must succeed. Keep `unity/**` authoritative and restore canonical runtime wiring before the final full-game APK.

The experimental bootstrap workflow may cache only `unity-bootstrap/Library/`, after APK validation. Never cache the Unity Editor/Android toolchain, Unity Hub state, credentials, license material, or the official game's `unity/Library/`. Treat GitHub cache expiry and eviction as possible.

**Why:** the user wants the full official game represented through cumulative full APKs, with only 5–7% of official C# added per build so each run can reuse the Unity project cache; intermediate APKs are not for use. The user clarified that a successful workflow with a validated APK is a passing stage even if Unity's BuildReport has a small error counter; log those counts for later collection instead of blocking the migration. The source project and live Supabase must remain intact. The earlier editor/toolchain cache was retired; project import cache is a separate, narrower scope.

**How to apply:** Before every Vexforge milestone, verify the branch/base and clean tree; keep client behavior within existing server contracts; keep both Unity workflows manual. For Bootstrap, use the manifest's fixed denominator, add 5–7% canonical C# per stage, preserve prior slices and the separate package ID, and build the full accumulated APK only after the previous APK passes workflow and artifact checks. Record BuildReport counters without treating them alone as a failed stage; collect them for later review. Intermediate scenes/runtime may be disconnected, but compilation must succeed. Record and later remove any temporary compile seam; restore canonical source/scene wiring before full-game claims. Cache only `unity-bootstrap/Library/` after successful APK validation. Stop on actual workflow/artifact failure; never imply full parity or device verification without evidence.
