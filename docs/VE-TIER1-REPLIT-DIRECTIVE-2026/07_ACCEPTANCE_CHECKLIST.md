# VEXFORGE — CRITERIOS DE ACEPTACIÓN

## Experiencia
[ ] Las cinco pantallas se sienten como un mismo juego.
[ ] No parecen un ERP, dashboard o panel CRUD.
[ ] La escena/objeto de cada dominio tiene identidad.
[ ] Existe una jerarquía clara entre gameplay, progresión e información.
[ ] El usuario entiende qué puede hacer sin leer una pared de texto.

## FOJA
[ ] Hay sensación de vida en idle.
[ ] Hay profundidad/parallax si el dispositivo lo tolera.
[ ] Hay hotspots reales.
[ ] El scroll descubre contenido.
[ ] Volver a FOJA se siente como regresar a la base.

## BATALLA
[ ] El acceso a PvP se siente como entrada a una arena.
[ ] Matchmaking tiene estados claros.
[ ] El usuario no ve detalles de motor/QA como presentación principal.

## CARTAS
[ ] La carta es protagonista.
[ ] La búsqueda/filtro es rápida.
[ ] El detalle tiene presencia.
[ ] La colección se siente coleccionable.

## MAZO
[ ] Construir un mazo es rápido.
[ ] Las validaciones ayudan.
[ ] El deck tiene identidad visual.
[ ] Existe un camino natural hacia la batalla.

## PERFIL
[ ] El usuario se reconoce como Forjador.
[ ] El progreso está contado como legado.
[ ] Estadísticas y logros son legibles sin dominar la experiencia.

## Performance
[ ] Sin jank evidente durante scroll.
[ ] Sin fugas de memoria observables.
[ ] Sin carga excesiva de assets en el primer render.
[ ] Sin degradar la experiencia en dispositivos Android modestos.
[ ] Sin aumento injustificado del APK.

## Integridad
[ ] No se rompen rutas existentes.
[ ] No se cambia auth/RLS/RPC/backend sin necesidad.
[ ] No se inventan datos para cubrir huecos.
[ ] No se crean rutas ficticias.
[ ] Se reutilizan fuentes canónicas existentes.

## Dirección de arte
[ ] Es reconociblemente VEXFORGE.
[ ] No parece copia de Shadowverse, Hearthstone, Pokémon, MTG, Master Duel o Marvel Snap.
[ ] Los efectos sirven a la lectura.
[ ] El motion tiene propósito.
